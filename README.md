## Key Features

- **Dual-LLM with automatic fallback** — Groq (primary, low-latency) and Gemini (fallback). If one fails, the other takes over transparently.
- **Zero-setup Demo Mode** — works out of the box with no API keys; mock questions and evaluation reports let you explore the full UI flow instantly.
- **Synchronized voice interview** — real Text-to-Speech questions and Speech-to-Text answers using the browser Web Speech API, with strict sequencing so the mic never records its own speaker.
- **Intelligent OCR pipeline** — handles digital PDFs, scanned PDFs, and images with a three-tier chain: `pypdf` → Tesseract/PaddleOCR → client-side Tesseract.js (no system dependencies needed on the candidate's machine).
- **8-question structured interview** with a role-aware state machine: Introduction → Projects → Challenges → AI Fundamentals → Generative AI → Automation → System Design → Closing.
- **Detailed evaluation report** — overall score (0–100), hire verdict, per-question feedback, and skills ratings, generated by the LLM and stored in the database.

## Getting Started

### Prerequisites

- **Python 3.10+** and **Node.js 18+**
- Tesseract OCR _(optional — only needed for server-side OCR on scanned PDFs; browser OCR works without it)_

### 1. Clone the repo

```bash
git clone https://github.com/sarandeep47/ai-interviewer.git
cd ai-interviewer
```

### 2. Configure environment variables

Copy the example file and fill in your keys:

```bash
cp backend/.env.example backend/.env
```

Then edit `backend/.env` (see [Environment Variables](#environment-variables) below).

### 3. Install dependencies

```bash
# Backend
cd backend
python -m venv venv
.\venv\Scripts\activate      # Windows
# source venv/bin/activate   # macOS/Linux
pip install -r requirements.txt
cd ..

# Frontend
cd frontend
npm install
```

### Running the Project

From the repo root (`ai-interviewer/`):

```powershell
.\start.ps1
```

| Service | URL |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:8000 |
| API Docs (Swagger) | http://localhost:8000/docs |

## Environment Variables

Create `backend/.env` (use `backend/.env.example` as a template):

```env
# AI Providers — omit both to run in Demo Mode
GEMINI_API_KEY=your-gemini-api-key-here
GROQ_API_KEY=your-groq-api-key-here

# Database — defaults to local SQLite
DATABASE_URL=sqlite:///interview_db.db

# CORS — comma-separated list of allowed frontend origins
ALLOWED_ORIGINS=http://localhost:5173,http://localhost:3000

# Model overrides (optional)
GROQ_MODEL=openai/gpt-oss-120b
GEMINI_MODEL=gemini-2.5-flash
```

| Variable | Required | Default | Notes |
|---|---|---|---|
| `GEMINI_API_KEY` | No | — | Omit for Demo Mode |
| `GROQ_API_KEY` | No | — | Omit for Demo Mode |
| `DATABASE_URL` | No | `sqlite:///interview_db.db` | Use `postgresql://` for production |
| `ALLOWED_ORIGINS` | No | `localhost:5173, localhost:3000` | Comma-separated; set your prod domain here |
| `GROQ_MODEL` | No | `openai/gpt-oss-120b` | Any Groq-compatible model ID |
| `GEMINI_MODEL` | No | `gemini-2.5-flash` | Any Gemini model ID |

## API Endpoints

## Troubleshooting

**"Why is the app running in Demo Mode?"**
Neither `GEMINI_API_KEY` nor `GROQ_API_KEY` was found in `backend/.env`. Add at least one key and restart the backend.

**"Resume upload fails or returns a parsing error."**
Check the file is under 10 MB. If the PDF is scanned (image-based), the backend will attempt OCR — if Tesseract is not installed, the response will include `"status": "client_ocr_required"` and the browser's Tesseract.js will take over automatically.

**"CORS error in the browser console."**
Your frontend origin is not in the `ALLOWED_ORIGINS` list in `backend/.env`. Add it (e.g. `http://localhost:5173`) and restart the backend.

**"PostgreSQL migration error on startup."**
If you see `column already exists` errors, they are safe to ignore — `init_db()` wraps all `ALTER TABLE` statements in try/except and continues. If you see a connection error, verify `DATABASE_URL` in `backend/.env` is correct and the database is reachable.

## Contributing

Contributions are welcome! Here's what to know before submitting a PR:

**Running checks:**
There is currently no automated test suite (no pytest config, no vitest). `backend/test_models.py` is a manual smoke-test script you can run directly (`python backend/test_models.py`) to verify your API keys connect correctly. If you add features, please include a manual verification step in your PR description.

**Code style:**
- Backend: follow standard PEP 8; keep service logic in `backend/services/`.
- Frontend: TypeScript strict mode; keep component logic in `App.tsx` until a component split is warranted.

**Submitting a PR:**
1. Fork the repo and create a branch (`git checkout -b feat/your-feature`).
2. Make your changes, test manually, and update the relevant section of this README if behavior changes.
3. Open a PR against `main` with a clear description of what changed and why.

### Monorepo Structure

1. **Frontend (`/frontend`)**: React 19 + TypeScript + Vite, custom CSS glassmorphic design, Lucide React icons.
2. **Backend (`/backend`)**: FastAPI + Uvicorn, SQLAlchemy ORM, SQLite (dev) / PostgreSQL (prod).
3. **Orchestration**: `start.ps1` launches both servers in separate terminal windows with auto-reload.

---

### LLM Provider Strategy

The service uses a **dual-LLM waterfall**:

- **Groq** (`openai/gpt-oss-120b` by default) — primary for real-time conversation (optimized for latency).
- **Gemini** (`gemini-2.5-flash` by default) — primary for resume extraction (better structured output quality); fallback for conversation if Groq fails.
- If both fail, the system falls back to local heuristics (regex + keyword matching).
- If neither key is configured: **Demo Mode** — fully mock responses, no API calls.

Resume extraction output fields: `candidate_name`, `candidate_email`, `skills`, `experience_level`, `summary_evaluation`.

**Local Parsing Fallbacks (Demo Mode or LLM failure):**
- Email → regex match
- Name → first 6 lines; checks for 1–4 capitalized words; skips header/location keywords
- Skills → curated keyword scan (up to 6 matches)
- Experience → `senior`/`lead` → Senior; `junior`/`intern` → Entry-level; else Mid-level

---

### Resume Parsing & OCR Pipeline

Three-tier chain triggered on upload:

1. **`pypdf` text extraction** — fast, works on native digital PDFs.
2. **Backend OCR** — if extracted text < 150 characters (scanned PDF), `PyMuPDF` renders pages as images and runs Tesseract (→ PaddleOCR fallback). File size capped at **10 MB** (HTTP 413 if exceeded).
3. **Browser OCR** — if backend OCR fails or Tesseract is not installed, backend returns `"status": "client_ocr_required"`. The React app then activates Tesseract.js in-browser — no system dependencies needed on the candidate's machine.

### Interview State Machine — 8 Questions (indices 0–7)

| Index | Stage | Description |
|---|---|---|
| 0 | Introduction | Welcome by name; ask candidate to introduce themselves |
| 1 | Projects | Walk through a specific project, architecture, and contributions |
| 2 | Challenges | Biggest technical challenge and how they resolved it |
| 3 | AI Fundamentals | ML concepts — overfitting, bias-variance, model evaluation |
| 4 | Generative AI | LLMs, prompt engineering, RAG, hallucinations, vector DBs |
| 5 | Automation | AI ops, monitoring, model downtime, API failure handling |
| 6 | System Design | Scalable AI platform design, concurrency, cost reduction |
| 7 | Closing | Mindset/learning assessment and candidate questions |

**Question Diversity Rules:**
- Each generated question is similarity-checked against all previous questions using SequenceMatcher ratio (threshold: 0.75) and Jaccard similarity on meaningful words (threshold: 0.45).
- Rejected questions are passed back to the LLM on the next retry.
- Up to 3 retry attempts before falling back to preset questions.

---

### Answer Validation Logic

Each candidate answer is classified as one of:

| Status | Trigger | Outcome |
|---|---|---|
| `ANSWERED` | Relevant, substantive response | Index advances |
| `IRRELEVANT` | Off-topic or evasive (1st time) | One clarification follow-up; index holds |
| `IRRELEVANT` | Off-topic or evasive (2nd time) | Auto-advance to next index |
| `SKIPPED` | Explicit skip request | Index advances |
| `I_DONT_KNOW` | Explicit "I don't know" | Politely acknowledged; index advances |

**Background LLM Analysis:** After upload, fast local parsing returns immediately. A `BackgroundTasks` job then calls the LLM for high-fidelity metadata (name, skills, experience) and updates the DB without blocking the user.

---

### Voice Interaction & Timer Rules

- **TTS** — Browser `SpeechSynthesis`. Markdown symbols stripped before speaking.
- **Strict TTS/STT sequencing** — microphone disabled while AI is speaking; recording starts only after the `onend` callback fires.
- **Idle Timer (10 seconds)** — starts after AI finishes speaking:
  - *Q0*: Plays "Are you there, [Name]?" nudge — once per question.
  - *Q1–7*: Plays skip phrase; auto-submits `"Candidate did not respond"`.
- **Recording Timer (15 seconds)** — visible countdown while recording; submits whatever was transcribed on expiry (or `"Candidate did not respond"` if nothing captured).
- **Mic stream cleanup** — `streamRef` tracks the active `MediaStream`; all stop/cleanup paths call `getTracks().forEach(t => t.stop())` to prevent browser mic leaks.

Server-side audio transcription is available at `POST /api/transcribe` using **Groq Whisper Large V3**. Falls back to a mock string if `GROQ_API_KEY` is not set.

---

### Session Termination (no_show)

Frontend calls `POST /api/sessions/{id}/terminate` when the candidate is idle before the intro. Session is marked `no_show` **only if** no user messages exist and `current_question_index` is still 0. The report endpoint returns a "Session Terminated" state rather than crashing on null `final_feedback`.

---

### Evaluation Report

After all 8 questions, the LLM generates:

- `overall_score` (0–100)
- `verdict` (Strong Hire / Hire / Borderline / No Hire)
- `summary`, `strengths`, `improvements` (arrays)
- `technical_skills_rating` and `communication_skills_rating` (out of 10) with comments
- `qa_breakdown` — per-question feedback

The session is marked `"completed"` **only after** `generate_final_feedback()` returns successfully. A failed LLM call will not leave the session permanently stuck with null feedback.
